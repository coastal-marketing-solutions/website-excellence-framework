# CR-034 — Bing Webmaster Tools + IndexNow and Moz backlink tracking as highly recommended default-stack layers

**Status:** Pending Governance Board approval. Implemented on branch `wef-cr-034-search-authority-tracking`.
**Number note:** `_change-requests/` tops out at CR-032. CR-033 is skipped because another context
has an uncommitted `assets/CR-033-DRAFT-Engagement-KB-Conformance.md` in flight (RETRO-017
collision avoidance). Re-check the next-free number immediately before merge.

## Problem

The default stack (Governance Sec. 13.4) measured search visibility through Google alone (GA4 +
Search Console). Nothing in the method asked an engagement to:

1. **Register the site with Bing Webmaster Tools or push URLs through IndexNow.** Bing's index feeds
   Microsoft Copilot, DuckDuckGo, Yahoo and other engines and AI answer surfaces, so a Google-only
   setup leaves those discovery paths unmonitored and dependent on passive crawling.
2. **Record a backlink / authority baseline at launch.** Without a dated baseline, the post-launch
   program (SG11.5) can't tell whether link-building or content work moved authority. Spam-link
   acquisition on new domains also goes unnoticed, or gets "fixed" with an unnecessary disavow.

## Evidence (originating engagement, client detail minimized)

On a real-estate engagement (2026-10-05), both connections took under an hour with free tiers:

- **Bing:** the property was added through "Import from Google Search Console" and the sitemap was
  listed. The SEO plugin's instant-indexing (IndexNow) feature already had a key and was
  submitting `post,page`, so scheduled blog posts are now pushed to IndexNow on publish. A live
  Bing Webmaster API call succeeded.
- **Moz:** a live API call returned DA 4 and 11 linking root domains. **Every one was automated
  spam** (link farms, counterfeit retail, "SEO boost" domains). Without the baseline, that site
  would have been assumed to have a small but real link profile. The correct disposition was
  "record, don't disavow (no manual action)", plus a list of genuine link sources to pursue.
- **Credential handling held:** the client created the accounts and pasted both keys into a local
  tool config file. Neither key reached the KB, the repo, page content or chat.

## Why "highly recommended" rather than standing-mandatory

Both depend on the client creating third-party accounts and generating keys, which an engagement
can't do on the client's behalf (Sec. 13.4.5). Making them mandatory would block SG10.5 exit on a
client action. "Highly recommended + Charter opt-out" keeps them on every engagement's path while
recording any deliberate exception.

## Not changed

No Industry Module changes: the setup is vertical-independent. Module-specific link sources (for
example real-estate citation sites) belong in each Module's local SEO guidance, not here.
