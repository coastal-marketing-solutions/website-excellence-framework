# CR-023 — RETRO-018: rendered-mockup requirement as a standalone checklist line *(Working Draft)*

**Status:** Pending Methodology Governance Board approval

Added **`RETRO-018`**, a real recurrence of `RETRO-001`'s exact failure pattern despite that entry's prior fix: a live real estate engagement completed Stage Gate 7 (Visual Design System) and Stage Gate 7.5 (Prototype Validation) using only written specifications and a text-based tournament scorecard, never actually invoking an AI design tool to produce a rendered mockup — undetected until Stage Gate 10.5, when the client asked to move to "the design portion" and discovered no render had ever been made. Root cause: Sec. 10.1's "complete key-page-template renders, not sketches" language existed as workflow-step prose but was never restated as an explicit, standalone Checklist line, so a detailed written specification could satisfy a literal reading of the Checklist without producing the actual artifact. **Fix:** Stage Gate 7 Sec. 4 (Outputs) and Sec. 11 (Checklist), and Stage Gate 7.5 Sec. 11 (Checklist), now state as standalone checklist lines — not just workflow prose — that at least the Homepage and one representative key-page template must exist as an actual rendered image/file from a named AI design tool or human designer before either gate is complete; a written specification, however detailed, is explicitly declared insufficient on its own, and skipping this requires a `GOVERNANCE-EXCEPTION` entry, not a default continuation. **Pending formal Governance Board approval.**
