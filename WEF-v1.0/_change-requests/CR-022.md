# CR-022 — Cross-Engagement Contribution Pipeline

**Approved By:** Methodology Governance Board

Added the **Cross-Engagement Contribution Pipeline** (Governance, Sec. 15.6), a direct response to RETRO-017: with multiple engagements (mortgage lending, real estate) running concurrently, a single Change Request (CR-019) was independently staged as three overlapping branches in different working environments, because nothing checked whether the finding was already in flight before a branch was created. **This CR's own numbering collided with CR-021, above, for the same reason** — both were drafted concurrently as "CR-021" (this one originally as RETRO-013) before either had visibility into the other; renumbered to CR-022/RETRO-017 on discovery, which is itself now cited in RETRO-017 as live evidence of why the fix is necessary. The fix is a three-layer discipline — per-engagement `WEF-Candidate-Findings.md` capture logs (Reusable Templates, Sec. 23.1), a mandatory dedup check against the Revision Log and open branches/PRs before any new `wef-cr-*` branch is created, and CR-number reservation (re-checked immediately before merge) before work begins — plus the new `wef-sync` skill, which automates the scan/dedup/reserve/batch cycle across every active engagement. New engagements are scaffolded with the candidate-findings log by default going forward (New Engagement skill, Step 6); existing active engagements are backfilled as a one-time rollout. **Note for the next formal version consolidation:** this CR is adopted and logged here, but no new top-line Version History entry was minted for it, since Version 1.4 (Working Draft) already sits reserved for CR-020's still-pending batch — reconcile version numbering for CR-020, CR-021, and CR-022 together at the next Governance Board review rather than resolving it unilaterally here.
