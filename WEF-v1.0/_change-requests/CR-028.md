# CR-028 — Revision Log body migration (F-4) *(Working Draft)*

**Status:** Pending Methodology Governance Board approval
**Companion audit:** [`assets/WEF-ICM-Architecture-Review-2026-09-07.md`](../../assets/WEF-ICM-Architecture-Review-2026-09-07.md), finding **F-4**

## Problem

`00-Front-Matter.md`'s Revision Log was an index that had absorbed content payload — rows CR-014…CR-027 each carried 5–15 lines of "what changed and why." ICM: *the catalog holds no books.* Two observed consequences: repeated CR-number collisions (CR-021/CR-022, CR-024/CR-025) because a hand-maintained index drifts (invariant 9); and reading the log to find "the highest CR number" — which `wef-sync` Step 4 requires every pass — had become a non-trivial scan of a wall of prose.

## Change

1. Created `WEF-v1.0/_change-requests/` — one `CR-0NN.md` per CR with a body (CR-005…CR-028), each carrying the full prose previously inline in its Revision Log row, verbatim, plus YAML frontmatter (`id`, `date`, `status`, `sections`, `retros`, `supersedes`, `superseded_by`). The single "CR-001 through CR-004 → see MWEF" row stays in the Revision Log unchanged.
2. Reduced the Revision Log to a thin index: `Change ID · Date · Section(s) · One-line summary · Status · Link`, the link pointing to `_change-requests/CR-0NN.md`.
3. Added `_change-requests/CONTEXT.md` — folder contract, the frontmatter schema, and the rule that the next free CR number is `max(id) + 1` read from these files, not from the prose log.
4. Pointed `wef-sync` Steps 3–4 and the Multi-Context Reconciliation Protocol (rule 9) at `_change-requests/` frontmatter as the source of the next free number; the dedup check still also consults open branches/PRs.
5. Added `_change-requests/` to the `AGENTS.md` "Where things live" table.

Deferred (optional, separate): generating the thin table from `_change-requests/*` frontmatter by script so it cannot drift. Not required — the thin hand-maintained table is already a large improvement.

## Why its own CR, not part of CR-027

~26 new files plus a rewrite of the single most cross-referenced table in the manual. Every `see CR-0NN` reference elsewhere keeps resolving (they are prose references to an ID, and the ID still exists), but a reviewer needs to confirm that deliberately, on its own.

## Validation

- Every moved CR's prose preserved verbatim in its `_change-requests/CR-0NN.md`.
- Thin table's one-line summaries are genuinely one line.
- `retros:` frontmatter cross-links resolve to Governance Sec. 15.4 entries.
- `wef-sync` and the Multi-Context Reconciliation Protocol both point at the new next-free-number source.
- `git diff --check` clean; all Markdown links resolve.
