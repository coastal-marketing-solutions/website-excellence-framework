# CR-038 — Channel measurement: phone contacts and call tracking, AI-assistant referrals, Google Business Profile

**Number note (2026-10-14):** drafted as CR-037; renumbered to CR-038 because CR-035 is taken by `wef-cr-035-intake-web-form` (Intake web form). Re-check the next-free number immediately before merge.

**Status:** Draft — not yet proposed to the Governance Board. Proposed wording only; no canon
methodology or Industry Module file has been edited. (Frontmatter uses the schema value
`Working Draft`.)
**Source:** `assets/WEF-Analytics-Gap-Review-2026-10-05.md`, gaps G-8, G-9, G-11, **with a
correction to G-9** (see Evidence).
**Depends on:** CR-036 (the `contact` event in the default taxonomy) and CR-037 (Reusable Templates
Sec. 7.4 part 8 Link-Tagging Standard). Pairs with CR-034 (Bing/IndexNow feeds Copilot and other AI
answer surfaces; this CR measures the traffic those surfaces send back).
**Scope:** split between Core and Module:

| Item | Core or Module |
|---|---|
| `contact` event on every tel:/mailto:/SMS link | **Core**, all engagements that display a phone number or email |
| AI Assistant channel reporting | **Core**, all engagements |
| Call tracking with dynamic number insertion (DNI) | **Module Injection Point**: each Industry Module states expected / optional / not expected |
| GBP link tagging and GBP Performance review | **Module Injection Point** (local verticals): each Module states expected / optional / not applicable |
| NAP integrity gate when call tracking is used | **Core** rule, triggered by the Module choice |

## Problem

1. **Phone conversions are under-measured (G-8).** Many verticals (real estate, home services,
   legal, medical, mortgage) convert by phone. Nothing requires a `tel:` click to be tracked, and
   nothing governs call tracking. Dynamic number insertion is the main way to attribute calls, but
   if a tracking number leaks into schema, the footer source or citations, it damages the NAP
   (name, address, phone) consistency that local SEO depends on.
2. **AI-assistant referrals are not reported (G-9).** WEF does GEO/AI-visibility work, and CR-034
   adds Bing/IndexNow because Bing feeds Copilot. But nothing in SG10.5 or SG11.5 asks anyone to
   look at the visits AI assistants send back.
3. **Google Business Profile is not measured (G-11).** For local verticals, GBP is often the top
   local entry point. Core methodology has no GBP coverage at all. A search of `WEF-v1.0/` for
   "Google Business Profile" or "GBP" finds no Core hits. Untagged GBP website clicks are reported
   as generic organic or direct traffic, and nobody reviews GBP Performance (calls, website clicks,
   direction requests).

## Evidence (originating engagement, client detail minimized)

A real-estate engagement reviewed on 2026-10-05:

- **`contact` was planned but not built.** The engagement's measurement plan defined a `contact`
  event for tel:/mailto: clicks, but the child theme implemented only two events (a listings click
  and `generate_lead`). Phone and email contacts, a primary channel for the vertical, went
  uncounted.
- **Correction to G-9: GA4 already has a built-in channel.** The gap review proposed a custom
  "AI Assistants" channel group. On the live property, GA4's **default channel group already
  includes an "AI Assistant" channel**, so a custom channel group is **optional**. It is needed only
  when a required AI source is not being classified into that channel. The requirement therefore
  becomes: report the built-in channel, and confirm which referrers it catches.
- **Custom channel group save failed in the UI.** An attempt to save a custom channel group
  failed in the GA4 interface. The workable fallback was to rely on the built-in channel plus a
  saved exploration filtered on session source. The checklist should name that fallback rather
  than let a UI failure block the gate.
- **GBP and email links were untagged.** Both were on the engagement's apply-now list (GBP website
  link and CRM email links). The GBP item is covered here, the email item in CR-037.

### Insert A — Prompt 10.5.7 (copy-paste, any engagement)

```
Set up channel measurement for [Client Name]'s site [https://domain.com]
(GA4 property "[property name]"), per the Integration Requirements Spec
and the active Industry Module's call-tracking and GBP expectations.
Follow Governance Sec. 13.4.4 (one writer; rendered output is the truth)
and Sec. 13.4.5 (credentials).

Ground rules:
- You never create accounts, enter passwords, or type API keys. I (or the
  profile/account owner) sign in to Google Business Profile and any
  call-tracking provider; you tell me exactly what to change and verify
  the result.
- No personal data in any event, parameter or URL.
- Changes to the GBP profile are made by the owner or on the owner's
  explicit OK; some GBP edits can trigger a Google review of the profile.

Steps:
1. Contact events: find every tel:, mailto: and SMS link in the rendered
   site (header, footer, CTAs, schema-adjacent blocks). Make each push
   {event: 'contact', method, cta_location, page_type} to the dataLayer
   through the single tag owner. Show each in DebugView from a logged-out
   private window. Mark contact as a key event if the Module says calls
   are expected.
2. AI Assistant channel: in GA4 Traffic acquisition (session default
   channel group), confirm the built-in AI Assistant channel exists. Then
   list session sources matching
   chatgpt|openai|perplexity|copilot|gemini|claude|deepseek|meta\.ai
   and state which channel each lands in. Only if a required source is
   unclassified, propose a custom channel group (I approve). If the UI
   fails to save it, create a saved exploration filtered on that session
   source regex instead and log the fallback in the Decision Register.
3. GBP (only if the Module's GBP expectation applies): give me the exact
   tagged URL for the GBP website field:
   https://domain.com/?utm_source=google&utm_medium=organic&utm_campaign=gbp
   (and the appointment-link variant with utm_content=appointment). After
   I save it, open the profile's link from a private window and show the
   tagged session in Realtime. Add the row to the Link-Tagging Standard.
4. Call tracking (only if in scope): confirm with me the provider, the
   sources that should see a tracking number, and the canonical NAP number.
   Install the DNI script through the single tag owner, under the consent
   category in the spec. Then prove: view-source, schema and footer still
   show the canonical number; only the displayed number swaps, and only
   for the defined sources; one test call shows source attribution in the
   provider. Call recording stays off unless the Compliance/Standards
   Liaison has cleared the disclosure for the client's jurisdictions.
5. Record results in the Search Visibility Operations Plan (sources table,
   measurement plan Debug Test column) and the Capability Ownership Matrix.
Report each step as done, blocked, not applicable, or awaiting my
approval, with evidence.
```

## Why "core hook + Module injection point"

A `tel:` click and AI-assistant traffic mean the same thing in every vertical, so they are core. The
value of call tracking and GBP varies by vertical, and so do the risks (call-recording disclosure,
health and legal confidentiality). Those already live in each Module's Regulatory & Compliance
Landscape, so the Module states the expectation and Core enforces the NAP and consent rules wherever
it is used.

## Not changed

- **No Industry Module file is edited.** Insert C is a proposal for each Module's next revision,
  logged in that Module's own version history (part 12).
- **No new default-stack layer.** Call-tracking providers vary by client and are chosen in the
  Charter/Integration Requirements Spec. GBP is client-owned, not a stack component.
- **No GBP optimization guidance** (categories, posts, reviews). This CR measures GBP only; local
  SEO guidance belongs in each Module's SEO & Keyword Strategy (part 7).
- **G-9's custom channel group** is deliberately downgraded from "set up" to "only if needed",
  per the correction above.

## Open questions for the Governance Board

1. **Tracking number on GBP:** should WEF forbid a tracking number on GBP outright (as drafted:
   canonical number as primary), or allow the common pattern of a tracking number as primary with
   the canonical number as an additional phone?
2. **Default when a Module is silent:** is "call tracking optional, GBP expected for any
   location-based client" the right fallback until every Module carries the new part 10 values?
3. **Insert C values:** approve the proposed starting values as a batch here, or require a
   separate Module-level CR per Module?
4. **AI referrer list maintenance:** who owns the watch list of AI referrers (SEO Specialist per
   engagement, or a firm-level list reviewed at the Semiannual Review Cycle)?
5. **`contact` as key event:** should phone/email contact be a key event by default for every
   lead-generation engagement, or only where the Module marks calls *expected*?
