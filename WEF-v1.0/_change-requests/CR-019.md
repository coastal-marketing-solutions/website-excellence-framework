# CR-019 — Production-outage retrospectives (RETRO-006/007/008)

**Approved By:** Methodology Governance Board

Added three Engagement Retrospective Register entries from a live engagement's (mortgage lending vertical) production-outage-and-recovery incident. **RETRO-006:** a git deploy integration's target directory was misconfigured to the site's document root instead of the intended theme subdirectory, undetected for weeks until a routine push auto-deployed and deleted the entire live CMS installation (deploy syncs the target to exactly match the repo) — happened twice, once from the triggering push and once from a manual redeploy before the misconfiguration was fixed. **RETRO-007:** pushing a large full-file replacement through a code-hosting platform's browser-based virtualized code editor via simulated select-all/paste caused the new content to be inserted alongside the old rather than replacing it; the editor's on-screen state and a same-technique DOM-text-read verification both failed to catch this, because a virtualized editor never reflects the true full document once it exceeds the rendered viewport — only a raw byte-size/marker-occurrence check outside the editor caught it, after two prior recovery attempts using the same unreliable verification technique had already failed. **RETRO-008:** an analytics tag was QA-signed-off as "verified firing correctly" without a separate check for consent-gating, and ran unconsented tracking in production for multiple days before a client question (not the QA process) surfaced it. Hardened Development Sec. 10.5 with a mandatory pre-first-push deploy-target verification step; hardened Sec. 10.5-Sync's Tier 3 (GUI-only) guidance against paste-simulation into virtualized editors, requiring either an editor's native state-management API or a platform's file-upload path instead, verified by exact length and marker-occurrence rather than visual/partial-text inspection; added a Best Practices entry on not compounding mistakes mid-incident (don't re-run a failed automated repair tool; never restore an unverified backup). Hardened QA & Optimization Sec. 11 Checklist and Sec. 14 Common Mistakes to require analytics/marketing tags be verified consent-gated, not merely firing.
