# CR-024 — WPConsent default-stack layer + RETRO-019/020

**Approved By:** Methodology Governance Board

Two additions from the same real estate (Synergy Real Estate Group) engagement. **WPConsent as a standing default-stack layer:** added Cookie Consent / Privacy Compliance to the Sec. 13.4 default technology stack table (WPConsent), alongside Cloudflare and Microsoft Clarity, which are elevated from situational to standing defaults every engagement provisions unless the Charter documents an explicit exception — WPConsent applies uniformly because any lead-capture site may reach visitors in a GDPR/CCPA/CPRA-type jurisdiction, independent of whether the active Industry Module flags the vertical as regulated. Development Sec. 10.5's workflow, Checklist, and Alt-stack mapping updated to include WPConsent installation/activation/consent-gating verification alongside GA4/GSC/GTM/Clarity. **`RETRO-019`/`RETRO-020`:** surfaced while pushing city/situation pages' Rank Math scores toward the 79+ target via browser automation. `RETRO-019`: calling a Gutenberg SEO plugin's own Redux state-management API directly (`wp.data.dispatch('rank-math').updateSerpTitle(...)`, etc.) updated every place that read from the store — visible preview, even the live-computed SEO score — while never touching the dirty-field tracking the Save action actually reads, so the edit was silently dropped on save with zero in-session signal; driving the same edit through the real, visible form control (native property setter + dispatched `input`/`change` events) persisted correctly every time. Corrects Development Sec. 15's prior note, which had mischaracterized an earlier instance of this same pattern as a field-specific "anti-tampering guard" rather than identifying the actual mechanism. `RETRO-020`: the plugin's own bulk "Recalculate Scores" batch tool produced *worse* scores than before for content that had only improved (one page dropping by double digits); the live per-item analyzer, run by opening the same page in the block editor, computed a meaningfully higher and correct score for identical content. Establishes as standing default (not a fallback reached for after failure): never write into a plugin's client-side state store directly, only read from it; and treat any bulk/batch computation as an approximation to be sample-verified against its live per-item equivalent, never as ground truth on its own.
