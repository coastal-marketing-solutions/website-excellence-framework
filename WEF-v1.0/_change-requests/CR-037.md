# CR-037 — Lead attribution & closed-loop reporting: source capture on every lead, off-domain conversion surfaces, CRM-to-analytics feedback, default dashboard, annotations, email link tagging

**Number note (2026-10-14):** drafted as CR-036; renumbered to CR-037 because CR-035 is taken by `wef-cr-035-intake-web-form` (Intake web form). Re-check the next-free number immediately before merge.

**Status:** Draft — not yet proposed to the Governance Board. Proposed wording only; no canon
methodology file has been edited. (Frontmatter uses the schema value `Working Draft`.)
**Source:** `assets/WEF-Analytics-Gap-Review-2026-10-05.md`, gaps G-2, G-3, G-4, G-10, G-12.
**Depends on:** CR-036 (default event taxonomy, `dataLayer` contract, Prompt 10.5.5/11.5.4
numbering) and CR-034 (unmerged). Renumber the prompts if those are adopted in a different order.
**Scope:** Core (SG10 Integration Requirements Spec, SG10.5, SG11, SG11.5). The closed-loop
server-side feedback item (G-3) is **optional**: it applies only when a CRM with pipeline stages is
in scope. The existing SG10 Sec. 9 Module Injection Point (Module-typical CRM/system integrations)
supplies the destination system, and this CR adds no new Module injection point.

## Problem

1. **Leads lose their source at hand-off (G-2).** Forms post to a CRM, but nothing requires the
   lead record to carry *where the visitor came from*: UTM source/medium/campaign, ad click ID
   (`gclid`/`gbraid`/`wbraid`), landing page, first referrer. Without that, the CRM can't answer
   "which channel produced qualified leads", and the KPI Dashboard reports GA4 event counts as if
   they were business outcomes, which contradicts Reusable Templates Sec. 7.4 part 7 ("Separate
   leading search indicators from meaningful business outcomes").
2. **Lead quality never flows back (G-3).** The business outcome (a qualified lead, a closed deal)
   happens in the CRM. Nothing defines sending CRM stage changes back to GA4 (Measurement Protocol)
   or to an ad platform (offline conversions), so optimization runs on raw form submits.
3. **Off-domain conversion surfaces are invisible (G-4).** Booking, scheduling, checkout and chat
   tools often run on the vendor's domain. Governance Sec. 13.4.6 covers access control and
   routing for those domains, but no gate requires them to be **measured**.
4. **No default dashboard tool or annotation habit (G-10).** SG11.5 Sec. 4 requires a "KPI
   Dashboard Specification" but names no tool. Reusable Templates Sec. 7.4 part 2 lists
   "Launch/migration/change annotations" as a baseline field, but nothing requires an annotation
   in the analytics property itself when a release ships.
5. **Owned email links are untagged (G-12).** CRM nurture emails link back to the site without
   UTMs, so return visits from email are reported as Direct.

## Evidence (originating engagement, client detail minimized)

A real-estate engagement reviewed on 2026-10-05:

- **Source missing from the lead record.** The form → CRM bridge sent only a "Submitted from:
  [page URL]" note. No channel, campaign or click ID reached the CRM.
- **Fix applied, and it worked.** A small first-touch / last-touch script stored source data in the
  browser's `localStorage` (first-touch written once, last-touch refreshed on each tagged arrival).
  On submit, it filled a hidden `lead_source` field (plus UTM, landing page and referrer fields)
  that the bridge mapped to CRM contact fields. Stored values were channel metadata only, with no
  personal data. The storage is still a client-side store, so it needs a consent-category
  decision. This CR makes that decision explicit.
- **Booking was invisible until a thank-you page was added.** The highest-intent action, a booked
  call, ran on the CRM vendor's booking page on the vendor's domain. GA4 recorded nothing until the
  booking flow was set to redirect back to a site thank-you page that fires `generate_lead` with
  `lead_type: booking`. The vendor domain also had to be added to GA4's unwanted-referral list, so
  the return visit was not credited to the vendor (CR-036 Insert A).
- **Closed-loop events were already provisioned but unused.** The GA4 property listed
  `qualify_lead` and `close_convert_lead` among its key events, but nothing ever sent them.
- **The CRM API silently dropped fields** (tags and pipeline stage) while returning success. That
  is why the attribution mapping must be verified by reading the record back, not by trusting the
  bridge's response (same evidence as CR-036).

### Insert A — Prompt 10.5.6 (copy-paste, any engagement)

```
Implement lead attribution and off-domain conversion measurement for
[Client Name]'s site [https://domain.com], per the Integration
Requirements Spec's Lead Attribution Field Map and Off-Domain Conversion
Surface register. Follow Governance Sec. 13.4.4 (one writer) and
Sec. 13.4.5 (credentials).

Ground rules:
- You never create accounts, enter passwords, or type API keys, webhook
  secrets or Measurement Protocol secrets. I create them and paste them
  where you tell me; you verify without printing them.
- Store channel metadata only: no name, email, phone, address or
  free-text in any stored value, hidden field default, URL or event.
- Attribution storage follows the consent category recorded in the field
  map. If that category is declined, do not write the store; the hidden
  fields then submit empty or "not_consented".

Steps:
1. Attribution script (one implementation, recorded in the Capability
   Ownership Matrix): on each landing, read utm_source, utm_medium,
   utm_campaign, utm_term, utm_content, gclid, gbraid, wbraid, the landing
   page path and document.referrer. Write first-touch once and refresh
   last-touch on every tagged or referred arrival. Treat untagged
   arrivals as direct only if no last-touch exists.
2. Hidden fields: add the field-map fields (e.g. lead_source,
   lead_medium, lead_campaign, click_id, landing_page, first_referrer,
   first_touch_*, last_touch_*, ga_client_id where analytics consent is
   granted) to every lead form, and populate them on submit.
3. CRM mapping: map each hidden field to the named CRM contact field in
   the form-to-CRM bridge. Do not overwrite a contact's existing
   first-touch values on a repeat submission.
4. Off-domain surfaces: for each surface, implement the chosen method -
   (a) cross-domain linker configured in GA4 for the vendor domain;
   (b) vendor webhook -> server-side Measurement Protocol generate_lead
       with lead_type and the captured client ID; or
   (c) vendor redirect to a site thank-you page that pushes
       generate_lead (lead_type: booking/checkout/...) to the dataLayer.
   Add each vendor domain to GA4 unwanted referrals.
5. Verify: from a private window, arrive via
   [https://domain.com/?utm_source=test&utm_medium=test&utm_campaign=cr036]
   and submit a labelled test lead per form, then arrive direct and
   submit again. Read both records back from the CRM via a fresh read and
   show every attribution field. Complete one test booking per off-domain
   surface and show its event in DebugView or Realtime.
6. Record the field map, test evidence, and consent category in the
   Conversion Measurement & Operational Handoff Contract.
Report each step as done or blocked, with evidence.
```

### Insert B — Prompt 11.5.5 (copy-paste; optional closed loop)

```
Set up closed-loop lead reporting for [Client Name] using [CRM name]'s
pipeline stages and [https://domain.com]'s GA4 property.

Ground rules: I create the GA4 Measurement Protocol API secret (Admin ->
Data streams -> Measurement Protocol API secrets) and any CRM/webhook or
ad-platform credentials, and store them only in the sending system's
credential store. You never type or print them.

   ga_client_id (and click ID where ad campaigns run).

   qualify_lead, [Won/Closed] -> close_convert_lead (optionally

   lead_source and value/currency where defined. No personal data.

   Leads without a consented client ID are counted in the CRM report only.

   the event in GA4 (Realtime / DebugView for MP validation).
6. Build or update the Looker Studio KPI Dashboard: leads and qualified
   leads by channel from the CRM export, GA4 key events, Search Console
   clicks/impressions, with GA4 annotations visible on time series.
Report each step as done or blocked, with evidence.
```

## Why the closed loop is optional and the rest is core

Source capture, off-domain measurement, dashboards, annotations and email tagging cost little and
apply to every engagement that collects leads. Closed-loop feedback needs a CRM with real pipeline
stages, a webhook-capable plan, and a client-created API secret (Governance Sec. 13.4.5). Making it
mandatory would block SG11.5 on a client's CRM choice. It is therefore a conditional checklist item
with a ready-made prompt.

## Not changed

- **No Industry Module text changes.** Each Module's CRM/system integration pattern already feeds
  SG10 through the existing Sec. 9 Module Injection Point.
- **Governance Sec. 13.4.6 is unchanged.** Routing and access control for third-party domains stay
  where they are; this CR adds measurement only.
- **No change to the consent-gating test (RETRO-008)** or to CR-036's Consent Mode line.
  Attribution storage is classified under the existing consent tool's categories.

## Open questions for the Governance Board

1. **Consent category for attribution storage:** first-party channel metadata in `localStorage` or
   a cookie. Should WEF classify it as *analytics* (blocked until consent, as drafted), or allow a
   *functional/necessary* classification where counsel for the active jurisdiction agrees? This
   decides whether declined-consent leads arrive with a source.
2. **Off-domain default method:** should WEF prefer (c) the thank-you redirect (simplest, and it
   worked on the originating engagement) over (b) the webhook → Measurement Protocol, or leave the
   choice open as drafted?
3. **Looker Studio as a default-stack row:** should it sit in Governance Sec. 13.4's table (as
   drafted), or only be named inside SG11.5?
4. **Closed loop for engagements running paid ads:** should the optional item become *required*
   when the Charter includes Google Ads or other paid acquisition?
5. **Server-side events for non-consented leads:** is "count in the CRM report only" (as drafted)
   the right rule, or should consent state be captured on the lead and passed to the
   server-side sender?
