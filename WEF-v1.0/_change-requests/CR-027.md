# CR-027 — Systematise client intake + close ICM architecture gaps (F-1–F-7)

**Approved By:** Methodology Governance Board

Systematised client intake as a stage-00 skill (`intake`) that generates the client-facing questionnaire and ingests answers into a templated `01-research/01-WEF-Intake.md` edit-surface artifact, wired as the strongly-preferred (not required) first step of `new-engagement` and as a named SG1 input. Added one question to the canonical Intake Worksheet (Sec. 16.2): client-ranked priority target locations, distinct from full service area, feeding SG5 local-landing prioritisation and the Sec. 16.3 research brief; renumbered Sec. 16.2 Q9–Q38 to Q10–Q39. Reconciled the file-naming convention across every remaining chapter (Research, UX & Conversion, Design, Development, QA & Optimization, AI Agent Services): Governance Sec. 8.3 now defers to Reusable Templates Sec. 21.4 (`Title-Case-No-Version.md` in `output/`), and every `descriptive-name-v{N}.md` Required-Document name has been substituted with the real convention. Added a routing entry file to the framework repository itself (`AGENTS.md` + one-line `CLAUDE.md` pointer). Added a literal `assets/templates/engagement-KB/` skeleton for `new-engagement` to copy rather than re-derive. Marked the never-implemented `master-content-workbook` skill as outstanding and moved its procedure inline to Sec. 8.4. Additive/reconciling; no Stage Gate exit criteria, persona library, compliance landscape, Eight-Dimension standard, default technology stack, or prior engagement approval affected. Companion audit: `assets/WEF-ICM-Architecture-Review-2026-09-07.md`. **Revision Log body-migration (F-4) and the Governance-chapter split (F-8) from that audit are deliberately left to their own follow-up Change Requests.**
