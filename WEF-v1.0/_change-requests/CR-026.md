# CR-026 — Design Fidelity Reviewer role + RETRO-021

**Approved By:** Methodology Governance Board

Added **`RETRO-021`** and a new standing role, **Design Fidelity Reviewer** (Sec. 2.2): on a live real estate engagement (Discover the Alamo City), SG7.5 closed with a signed Executive Approval Record and the initial SG10.5 build passed its one-time Global Styles spot-check, but across many subsequent, independently-scoped content-expansion sessions the live site's visual output drifted from the approved direction — several named components (an audience-router card pattern, a distinctive commute-corridor motif, a light-card bio pattern, the site footer, header wordmark treatment) were never built to spec or were built structurally differently than approved, undetected because nothing between the initial spot-check and an unrelated workflow audit was specifically tasked with re-checking build output against the approved design. Compounded by a superseded pre-tournament design document that was never marked superseded after SG7.5 closed, so a later session cited it as current, and by the approved design's exact token/component values living only in unindexed rendered-mockup source files rather than an extracted quick-reference specification. **Fix:** the Design Fidelity Reviewer role (Sec. 2.2) runs recurring — not one-time — checks against the Design Constraints Package throughout Development and Post-Launch, and **holds direct remediation authority**: found drift against already-approved spec is corrected in the live build/code on the spot rather than only flagged for a later, unowned session, which is what let this drift compound silently in the first place; anything the spec doesn't already answer is escalated to the Visual Designer as a design decision, never resolved unilaterally, which is how the role stays distinct from the Visual Designer despite overlapping the Developer's code (Sec. 2.4). A corresponding RACI row (Sec. 2.3) and best-practice notes (Sec. 2.4) prevent the recurring cadence from being silently satisfied by the existing one-time SG10.5 spot-check, and clarify why remediation authority doesn't collapse the existing separation-of-duties rule; Development Sec. 06 SG10.5 now names this role as a Required Specialist and adds a recurring detect-and-remediate checklist line alongside the existing one-time spot-check; and a documentation-hygiene rule requires any superseded design document to carry an explicit, prominent superseded notice pointing to its replacement the moment the replacement is approved.
